# FoxMonitor

Прототип системы удалённого мониторинга для локального тестирования и обучения.
Клиент (C++, Windows) стримит экран и камеру на сервер (Python/FastAPI) по WebSocket,
веб-интерфейс (vanilla JS) показывает стримы, управляет клиентами, пишет записи и скриншоты.

```
site/
├── client/                  # C++ клиент (Visual Studio 2022, x64)
│   ├── FoxMonitor.sln
│   ├── FoxMonitor.vcxproj
│   ├── config.ini           # настройки клиента
│   └── src/
│       ├── main.cpp         # потоки, команды, reconnect
│       ├── wsclient.cpp/.h  # минимальный WebSocket-клиент (RFC 6455)
│       ├── jpeg.cpp/.h      # JPEG-кодирование через GDI+
│       ├── screen.cpp/.h    # захват виртуального рабочего стола (GDI)
│       ├── camera.cpp/.h    # веб-камера (MediaFoundation SourceReader)
│       └── config.cpp/.h    # парсер config.ini
├── server/                  # сервер + фронт
│   ├── server.py            # REST API + WebSocket-ретрансляция
│   ├── requirements.txt
│   ├── config.json          # (опционально) хост/порт/пароли
│   ├── static/              # веб-интерфейс (index.html, style.css, app.js)
│   └── data/                # записи, скриншоты, логи (создаётся при старте)
└── tools/
    ├── simulate_client.py   # симулятор C++-клиента (чистый Python, для тестов)
    └── test_ui_ws.py        # тест WS-канала веб-интерфейса
```

## Сборка и запуск

### 1. Сервер

```bash
cd server
pip install -r requirements.txt
python server.py
```

Сервер поднимется на `http://0.0.0.0:8080`.
По умолчанию: логин `admin`, пароль `admin123`, клиентский ключ `secret123`
(переопределяется через `server/config.json`):

```json
{
  "port": 8080,
  "client_key": "secret123",
  "users": { "admin": "admin123" }
}
```

### 2. Клиент (C++)

1. Открой `client/FoxMonitor.sln` в Visual Studio 2022 (Desktop development with C++).
2. Выбери `Release | x64`, собери (Build → Build Solution).
3. Рядом с `FoxMonitor.exe` положи `config.ini` (он лежит в `client/config.ini`):

```ini
host = 127.0.0.1        ; адрес сервера
port = 8080
client_id = pc1         ; имя машины
client_key = secret123  ; должен совпадать с серверным
screen_fps = 10
camera_fps = 5
jpeg_quality = 75
capture_screen = 1
capture_camera = 1
location = Офис 203, 3 этаж   ; местоположение машины — вкладка «Инфо»
```

> `capture_camera` — разрешение на камеру, но стрим включается только по требованию:
> когда в веб-интерфейсе открыта вкладка «Камера» (или нажата «Старт»), сервер шлёт
> клиенту `start`; при уходе с вкладки — `stop`. Сама по себе камера не работает.
>
> `location` — свободный текст с местоположением машины (офис, этаж, комната);
> показывается во вкладке «Инфо».

4. Запусти `FoxMonitor.exe` — клиент подключится сам и появится в веб-интерфейсе.

> Без тулчейна под рукой можно проверить весь стек симулятором:
> `python tools/simulate_client.py --id pc1`

### 3. Веб-интерфейс

Открой `http://localhost:8080`, войди (admin/admin123).

- Карточки клиентов с живым превью экрана, индикацией статуса и уведомлениями о подключении.
- «Смотреть» — модалка с вкладками Инфо/Экран/Камера/Файлы, запись, скриншот,
  слайдеры качества и FPS, стоп/старт стрима, сохранение текущего кадра. Камера
  транслируется только пока открыта вкладка «Камера» — при переключении или
  закрытии она выключается.
- Вкладка «Инфо»: имя и ОС машины, процессор, объём ОЗУ, аптайм, список мониторов
  с разрешениями и расположением на виртуальном столе, местоположение из config.ini.
- Вкладка «Файлы» — файловый менеджер удалённой машины: обзор дисков и каталогов,
  загрузка файла на ПК (с опцией «запустить после загрузки»), скачивание файла,
  запуск и удаление. Лимит одного файла — 8 МБ.
- «Скриншот» на карточке — мгновенный снимок.
- «Планировщик» — автоскриншоты каждые N минут.
- «Файлы» — записи (.mjpeg) и скриншоты со скачиванием.
- «Логи» — журнал сервера.

## REST API

| Метод | Путь | Описание |
|---|---|---|
| POST | `/api/login` | `{user, pass}` → `{token}` |
| GET | `/api/clients` | список клиентов и статусы стримов |
| GET | `/api/clients/{id}/info` | информация о ПК, мониторах, местоположении |
| POST | `/api/clients/{id}/fm/list` | `{path}` → список файлов (пустой path = диски) |
| POST | `/api/clients/{id}/fm/download` | `{path}` → содержимое файла (до 8 МБ) |
| POST | `/api/clients/{id}/fm/upload` | raw body + заголовки `X-File-Path`, `X-File-Run` |
| POST | `/api/clients/{id}/fm/run` | `{path}` → запуск файла на машине |
| POST | `/api/clients/{id}/fm/delete` | `{path}` → удаление файла/каталога |
| POST | `/api/clients/{id}/command` | `{command: start\|stop\|quality\|setfps\|screenshot, stream, value}` |
| POST | `/api/clients/{id}/record` | `{stream, action: start\|stop}` |
| GET | `/api/recordings`, `/api/recordings/{name}` | список/скачивание записей |
| GET | `/api/screenshots`, `/api/screenshots/{name}` | список/скачивание скриншотов |
| GET/POST | `/api/scheduler` | включение планировщика и интервал (сек) |
| GET | `/api/logs?n=200` | последние строки журнала |

Все, кроме login, требуют заголовок `Authorization: Bearer <token>`.

## Протокол (клиент ↔ сервер, WebSocket `/ws/client`)

- Текст (JSON): `{"type":"hello","id":...,"key":...}` при подключении;
  `{"type":"status","streams":{...}}` при изменении; команды с сервера — `{"type":"cmd",...}`;
  ответы файлового менеджера — `{"type":"fm","req_id":N,"action":"list|read|write|run|delete","ok":...}`.
- Бинарные кадры: `[kind:1 байт][len BE32][JPEG]`, где kind `1` = экран, `2` = камера,
  `3` = скриншот по команде (payload начинается с `1`/`2` — какой стрим сняли),
  `4` = файл от клиента (`[req_id BE32][size BE32][data]`), `5` = файл клиенту
  (`[req_id BE32][run u8][path_len BE32][path UTF-8][data]`).
- UI подписывается на `(client, stream)` через `/ws/ui` и получает кадры base64-JSON'ом.

## Удалённое управление

В модалке просмотра есть кнопка «Управление» — включает режим ремоут-контроля:

- движение мыши, клики (ЛКМ/ПКМ/средняя), скролл — по кадру стрима
- клавиатура: обычные символы (в т.ч. кириллица и Unicode), стрелки, Enter, Tab,
  Backspace, F1–F24, модификаторы (Ctrl/Shift/Alt) — комбинации работают
- сервер просто транзитирует события (`{"type":"input",...}` от UI к клиенту),
  клиент исполняет их через `SetCursorPos`/`mouse_event`/`SendInput`
- ESC не пересылается (локально закрывает модалку); режим выключается автоматически
  при закрытии модалки

Координаты из UI маппятся в виртуальный стол (`SM_XVIRTUALSCREEN` + пиксель кадра),
так что мультимониторные конфигурации работают корректно.

## Записи

Записи пишутся как сырой MJPEG-поток (`*.mjpeg`) — совместим с большинством плееров.
Конвертация в MP4 (если установлен ffmpeg):

```bash
ffmpeg -i pc1_screen_20260811_171553.mjpeg -c:v libx264 -pix_fmt yuv420p out.mp4
```
